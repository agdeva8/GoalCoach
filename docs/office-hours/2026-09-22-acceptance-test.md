## Purpose

This file is the falsifiable definition of "did we build the right thing?" for Sutra v2. It outlasts every architecture decision. If v2 ships and would not have changed the outcome in **7+ of 10** of these moments, v2 is wrong — regardless of how clean the code is.

This complements (does not replace) the CEO plan's verification gates at `docs/ceo-plans/2026-09-22-sutra-phase1.md`:
- Verification gates ask "did we build it right?" (D30 binary, D14 cohort)
- Acceptance test asks "did we build the right thing?" (10 moments)

Together: moment rubric (qualitative) + cohort gates (quantitative).

---

## How to use this

1. **Pre-build:** fill in 10 moments before any code lands. Real moments, not hypotheticals.
2. **Per-moment:** each moment has a date range, goal(s) involved, what you said to yourself, what actually happened, what the coach would have said.
3. **At each layer (2/3/4):** reviewers cite specific moments when raising scope conflicts or design trade-offs.
4. **At v1 ship:** walk through the 10 moments. For each, ask: "would the shipped product have changed the outcome?" Score pass/fail. ≥7/10 = ship. <7/10 = iterate.

## Scoring

At v1 ship:
- **Pass:** coach would have changed the outcome (earlier, more honest, less costly)
- **Neutral:** coach would have given the same advice the founder gave themselves
- **Fail:** coach would have missed it, gotten it wrong, or made it worse

Score: P = pass count, N = neutral, F = fail.
**Ship gate:** P ≥ 7. Anything below means the thesis is wrong or the build missed the wedge.

---

## Notes

- A "moment" can be a multi-day situation, a single conversation with yourself, a contradiction you didn't notice, an over-commitment you caught too late, or a half-promise you made on a Tuesday at 11pm.
- Skip the polished ones. The embarrassing, contradictory, "I told myself X and did Y" moments are the ones that prove the test.
- Re-read this file before every layer-2/3/4 review. Drift from the moments is drift from the thesis.
